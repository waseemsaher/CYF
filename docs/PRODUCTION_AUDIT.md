## Executive Summary

The Codeera platform has reached significant functional maturity across catalog browsing, payment submissions, quiz taking, and Telegram bot interactions. Core database migrations and unit/feature tests pass cleanly (`90 tests, 292 assertions`). Coding style adheres to PSR-12 via Laravel Pint, and static analysis satisfies Larastan Level 6 with zero reported errors.

However, this audit has identified **critical production blockers, security gaps, and architectural divergences** that must be resolved before deploying for real students and handling real monetary transactions.

## High-Priority Flags (Immediate Attention Before Go-Live)

1. **Production Seeder Danger (`DatabaseSeeder.php`)**:
   - `admin@example.com`, `teacher@example.com`, and `student@example.com` are seeded with the default password `password` unconditionally inside `DatabaseSeeder.php`. Because `scripts/deploy.sh` and `scripts/prod-init.sh` execute `php artisan db:seed --force`, these default accounts will be created on the production server, granting immediate superadmin access to anyone guessing default credentials.
2. **Wildcard Permissive CORS (`backend/config/cors.php:30-32`)**:
   - The regex pattern `'allowed_origins_patterns' => ['#^https?://.*#']` allows *any* external website to make credentialed cross-origin requests (`supports_credentials => true`), nullifying cross-origin protection.
3. **Telegram Webhook Secret Bypass When Unset (`TelegramController.php:98`)**:
   - `if ($secretToken !== '' && $receivedSecret !== $secretToken)` evaluates to false if `TELEGRAM_WEBHOOK_SECRET` is unset or empty, permitting arbitrary unauthenticated webhook payloads.
4. **Adapter Mismatch with DigitalOcean Runbook (`frontend/svelte.config.js`)**:
   - Frontend uses `@sveltejs/adapter-vercel` which outputs to `.vercel/output/`, while Nginx, Supervisor, PM2, and `deploy.sh` expect a Node.js SSR bundle at `frontend/build/index.js` generated by `@sveltejs/adapter-node`.
5. **Over 500 Hardcoded Arabic Strings (`frontend/src/routes/*`)**:
   - 20 Svelte files have hardcoded Arabic text without i18n translation functions (`t()`). Switching the UI to English leaves all administration, student dashboard, checkout, quiz, and course pages in Arabic.
6. **Hero Video Bandwidth Hazard (`frontend/static/videos/hero-bg.mp4`)**:
   - The hero background video is **16 MB**, severely degrading First Contentful Paint (FCP) and Largest Contentful Paint (LCP) on mobile and throttled connections.
7. **Missing Transactional Emails & Missing Auth Endpoints**:
   - `PaymentApprovedMail` and `PaymentRejectedMail` are defined as queued mailables but are **never dispatched** in `ApprovePayment` or `RejectPayment`.
   - Password reset and email verification flows are absent from backend routes and frontend UI.

### B. Money, Payments & Enrollment Correctness

#### 1. Integer Piaster Representation
- **Status**: ✅ Already correct
- **Location**: `backend/database/migrations/*`, `backend/app/Models/*`
- **Findings**: All currency amounts (`price_cents`, `list_price_cents`, `discount_cents`, `amount_due_cents`, `teacher_share_cents`, `platform_share_cents`) are strictly defined as integer piasters with integer casts in Eloquent models.

#### 2. Atomic & Idempotent Payment Approval
- **Status**: ✅ Already correct
- **Location**: `backend/app/Domain/Payments/Actions/ApprovePayment.php`
- **Findings**:
  - Encapsulated in `DB::transaction()`.
  - Employs pessimistic locking `Payment::query()->lockForUpdate()`.
  - Fully idempotent: checks `$payment->isApproved()` and returns existing `Enrollment` without duplicate execution or revenue redistribution.

#### 3. Immutable Price & Revenue-Share Snapshots
- **Status**: ✅ Already correct
- **Location**: `backend/app/Domain/Payments/Actions/SubmitPayment.php`, `ApprovePayment.php`
- **Findings**: `list_price_cents`, `discount_cents`, and `amount_due_cents` are snapshotted on payment creation. `teacher_share_percent`, `teacher_share_cents`, and `platform_share_cents` are frozen upon payment approval.

#### 4. Duplicate Payment-Proof Detection
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Domain/Payments/Actions/SubmitPayment.php`, `backend/app/Models/Payment.php:96`
- **Findings**:
  - `proof_hash` is computed using `sha256` and saved.
  - `hasDuplicateProof()` checks for duplicates.
  - *Weaknesses*: The check executes a subquery inside `PaymentResource.php`, causing an N+1 query problem across the payment review queue. There is no dedicated index on `(proof_hash, id)`, nor a stored `is_duplicate_proof` boolean column for query indexing.

#### 5. Discount Calculation & Edge Cases
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Domain/Catalog/Actions/CalculateCoursePrice.php`, `backend/tests/Feature/CatalogPricingTest.php`
- **Findings**:
  - Enforces best single discount, non-stacking, floor at zero.
  - Current unit tests cover basic percent vs fixed discounts, but lack tests for:
    - Multiple overlapping active discounts with equal discount values.
    - Global ('all') discounts vs course-specific discounts precedence.
    - Mid-request discount expiration during multi-step checkout.

#### 6. Enrollment Expiration & Access Revocation
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Console/Commands/RemoveExpiredTelegramMembersCommand.php`, `backend/app/Domain/Telegram/Actions/RemoveExpiredMembers.php`
- **Findings**:
  - Registered in console scheduler: `Schedule::command('telegram:remove-expired')->daily()`.
  - Removes expired users from Telegram groups/channels.
  - *Defect*: The action fails to update the database record `enrollment.status = 'expired'`. The records remain with `status = 'active'`, relying solely on query filters checking `expires_at > now()`.
  - Outbound Telegram API calls inside the command run inline synchronously rather than queued as jobs.

### C. Security Hardening

#### 1. Explicit Authorization on Every Endpoint
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/routes/api.php`, `backend/app/Http/Controllers/Api/*`
- **Findings**:
  - Endpoints have authorization checks, but `PaymentController.php` lines 87 and 105 use ad-hoc checks `if ($user->getKey() !== ...)` instead of `Gate::authorize()` or `$this->authorize()`, bypassing `PaymentPolicy`.
  - Admin controllers use manual `$this->authorizeAdmin()` helper methods rather than standard Spatie route middleware (`permission:payments.review`, `role:admin|superadmin`).

#### 2. Rate Limiting Coverage
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/routes/api.php`
- **Findings**:
  - `login` and `register` have `throttle:10,1`.
  - `payments` has `throttle:10,1`.
  - `telegram/webhook` has `throttle:60,1`.
  - Password reset endpoint is **completely missing** from the application.

#### 3. File Uploads Security & Validation
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Domain/Payments/Actions/SubmitPayment.php`, `backend/app/Domain/Learning/Actions/CreateCourseItem.php`
- **Findings**:
  - Payment proof: Re-encoded via GD (strips EXIF), randomized filename, private storage, signed temporary URLs for admin review.
  - Course learning materials (`CreateCourseItem.php:34-42`):
    - Uses `$file->getClientOriginalExtension()` instead of server-verified MIME detection (`getMimeType()`).
    - Permits archive formats (`zip`, `rar`), contrary to AGENT.md §6 ("Block executables/archives by default").
    - Hardcoded 50MB size limit instead of reading settings.

#### 4. Telegram Webhook Secret Verification
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Http/Controllers/Api/TelegramController.php:98`
- **Findings**:
  - Condition `if ($secretToken !== '' && $receivedSecret !== $secretToken)` allows unauthorized webhook calls if `TELEGRAM_WEBHOOK_SECRET` is unset or empty. It must fail closed (`deny by default`).
  - Webhook processing initiates synchronous HTTP calls to Telegram API instead of queuing jobs.

#### 5. Production Debug & Error Information
- **Status**: ✅ Already correct
- **Location**: `backend/bootstrap/app.php:21-25`, `.env.production.example`
- **Findings**: Stack traces and internal exceptions are suppressed when `APP_DEBUG=false`, returning standardized JSON error payloads.

#### 6. HTTPS, Cookie Security & Strict CORS
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/config/cors.php:30-32`, `frontend/src/lib/api/client.ts`
- **Findings**:
  - `cors.php` allows any origin pattern via `'#^https?://.*#'`.
  - `frontend/src/lib/api/client.ts` stores bearer tokens in `localStorage` instead of using Sanctum session cookies (violating AGENT.md §5).
  - `session.php` secure cookie flag defaults to null unless `SESSION_SECURE_COOKIE=true` is set.

#### 7. Security Headers
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/app/Http/Middleware/SecurityHeaders.php`, `deploy/nginx/cyf.conf`
- **Findings**:
  - `Content-Security-Policy` (CSP) is completely missing from both Laravel middleware and Nginx configuration.
  - `Strict-Transport-Security` (HSTS) is commented out in `deploy/nginx/cyf.conf` and missing from `SecurityHeaders.php`.

#### 8. Git Secrets Scan
- **Status**: ✅ Already correct
- **Location**: Git commit history
- **Findings**: History search across all branches and commits confirmed zero leaked API keys, tokens, or live credentials.

#### 9. Dependency Vulnerability Audits
- **Status**: ⚠️ Exists but weak
- **Location**: `backend/composer.lock`, `frontend/package-lock.json`
- **Findings**:
  - `composer audit`: PASSED (0 advisories).
  - `npm audit`: **FAILED** with 7 vulnerabilities (3 low, 3 moderate, 1 high) in `cookie` (<0.7.0) and `esbuild` (<=0.24.2) dependencies.

#### 10. Mass Assignment Protection
- **Status**: ✅ Already correct
- **Location**: `backend/app/Models/*`
- **Findings**: All Eloquent models use explicit `$fillable` arrays. No `$guarded = []` exists.

## Proposed Remediation Plan (Grouped PRs per AGENT.md §2a)

Following the owner's review of this audit report, fixes should be executed in small, focused, reviewable PRs in the following sequence:

1. **PR 1: Security & Seeder Hardening (Categories C & H)**
   - Remove demo users from production `DatabaseSeeder.php` (restrict to `local`/`testing`).
   - Fix permissive CORS regex in `backend/config/cors.php`.
   - Fix Telegram webhook secret verification to deny by default when token is empty.
   - Enforce CSP and HSTS security headers in `SecurityHeaders.php` and `cyf.conf`.
   - Update `PaymentController` to use `PaymentPolicy` authorization gates.

2. **PR 2: Architecture & Backend Seams (Category A)**
   - Extract domain Actions for `storeQuiz`, `storeQuestion`, `updateSection`, etc., in `AdminLearningController`.
   - Add missing `declare(strict_types=1);` to all PHP files.
   - Dispatch `PaymentApprovedMail` and `PaymentRejectedMail` on queues.
   - Fix enrollment expiry action to update database status to `expired`.

3. **PR 3: Database & Query Performance (Category D)**
   - Eliminate N+1 queries in `CatalogController`, `AdminPaymentController`, and `TeacherDashboardController`.
   - Add database indexes on `courses.status`, `enrollments.status`, `enrollments.expires_at`, and `attempt_answers.question_id`.
   - Add pagination to `AdminTeacherController` and `ContentBlockController`.
   - Add Redis caching for course catalog queries.

4. **PR 4: Frontend Infrastructure & Ops Alignment (Categories D & G)**
   - Switch SvelteKit adapter from `@sveltejs/adapter-vercel` to `@sveltejs/adapter-node`.
   - Compress `hero-bg.mp4` (from 16MB to <2MB) and convert `hero-poster.jpg` to WebP.
   - Clean up 84 unused CSS selectors in `+layout.svelte`.
   - Fix `npm audit` vulnerabilities.

5. **PR 5: SEO, Favicons & Metadata (Category F)**
   - Create brand `app-icon.svg` asset.
   - Generate favicon suite (16x16, 32x32, 180x180, webmanifest).
   - Add `robots.txt` and `sitemap.xml`.
   - Add canonical links, Open Graph tags, and Schema.org `Course` structured data.

6. **PR 6: i18n & Accessibility Completeness (Category E)**
   - Extract hardcoded Arabic strings into `src/lib/i18n/ar.ts` and `src/lib/i18n/en.ts`.
   - Unify `formatPrice` into a single localized utility.
   - Verify WCAG AA contrast for buttons and links.
